Security Operations

Where security strategy becomes daily operational practice

Learning Objectives

1
Support and conduct security investigations by preserving evidence, maintaining chain of custody, and resolving administrative, civil, criminal, and regulatory matters.

3

10
Manage physical security operations—facility access, environmental monitoring, guard forces, CCTV, and media vaults.
11
Integrate operational practices into a continuous security operations lifecycle that supports organizational resilience.

Key Terms & Concepts

Investigations & Evidence
Digital Forensics

The scientific preservation, extraction, identification, and documentation of digital evidence from computer systems and storage media for use in legal proceedings.

Chain of Custody

An unbroken, meticulously documented paper trail tracking the collection, custody, transfer, and analysis of physical or logical evidence during an investigation.

Admissibility

The legal threshold dictating whether evidence is reliable and has been legally gathered, allowing it to be formally introduced in court.

Volatile Evidence

Digital data stored in temporary media—such as CPU registers, cache, and RAM—that is permanently lost when a system is rebooted or powered down.

Locard's Exchange Principle

The forensic rule stating that anyone entering an environment leaves a trace and takes a trace with them. This applies to attackers leaving log entries and artifacts.

Non-Volatile Evidence

Data stored on persistent physical media, such as magnetic hard drives or solid-state drives, that remains intact after power is removed.

Monitoring & Logging
SIEM (Security Information & Event Management)

A centralized software platform that aggregates, normalizes, correlates, and analyzes security logs from across the enterprise in real time.

Event vs. Alert

An event is any observable state change on a system or network; an alert is a high-priority notification triggered when an event matches an attack signature.

Log Retention

The policy-driven duration for which log data must be preserved securely to satisfy compliance regulations and forensic investigation requirements.

Threat Intelligence

Actionable, structured data describing active adversaries, malware indicators, and vulnerability exploit vectors used to tune detection rules.

Configuration & Change Management
Configuration Baseline

The documented, approved standard configuration settings, service states, and patch levels defined for a specific platform type.

Hardening

The practice of minimizing a system's attack surface by closing unused ports, disabling unnecessary services, and changing default settings.

Change Advisory Board (CAB)

A cross-functional body of stakeholders that reviews, schedules, and approves high-risk change requests to ensure operational stability.

Rollback Plan

A documented, tested procedure used to revert a system to its pre-change state if a production deployment fails.

Configuration Drift

The unauthorized or undocumented deviation of a system's configuration over time from its approved baseline.

Emergency Change

An abbreviated change control workflow used to deploy critical fixes immediately to resolve active incidents, subject to post-implementation review.

Incident Management
Incident

An event that violates organizational security policies or threatens the confidentiality, integrity, or availability of enterprise assets.

Triage

The initial analysis and classification phase of incident response, used to determine severity, scope, and response priority.

Containment

Tactical response actions designed to isolate affected systems and stop an attack from spreading while preserving forensic evidence.

Eradication

The systematic removal of malicious files, backdoors, and persistence mechanisms after containment is established.

Lessons Learned

The final post-incident phase where the response team reviews the incident timeline to identify gaps and update security controls.

Playbook

A highly prescriptive, documented step-by-step checklist used by incident responders to manage specific threat types (such as ransomware).

Detection & Prevention
IPS (Intrusion Prevention)

An active, inline network security control capable of analyzing data packets and blocking malicious traffic in real time.

DLP (Data Loss Prevention)

Controls designed to monitor and block unauthorized transfers of classified data at endpoints, email gateways, or network boundaries.

Sandboxing

Executing untrusted, suspicious files within an isolated virtual sandbox to analyze their behavior safely.

Allow List / Block List

Allow lists explicitly permit only approved applications, IPs, or domains (default-deny); block lists explicitly deny known-bad entities (default-allow).

Endpoint Detection & Response (EDR)

Advanced host security tools that analyze real-time system telemetry and behaviors, enabling automated endpoint isolation and rollbacks.

Honeypot / Honeynet

Decoy systems or entire networks designed to attract, log, and analyze attacker behavior without risking authentic production systems.

Recovery & Continuity
Incremental Backup

A backup that copies only data that has changed since the last full or incremental backup, minimizing backup windows but complicating restores.

Differential Backup

A backup that copies all data modified since the last full backup. Restores require only the last full backup and the latest differential set.

RTO vs. RPO

RTO is the target time to restore systems; RPO is the maximum acceptable duration of data loss, driving backup frequency.

Immutable Backups

Backup data sets written in a write-once-read-many (WORM) format that cannot be modified, encrypted, or deleted during their retention period.

Hot / Warm / Cold Site

Hot sites are live, synchronized duplicates; warm sites contain configured hardware requiring data restores; cold sites provide only facilities.

Failover

The automatic, redundant switching of network traffic, applications, or databases to a secondary system when a failure is detected.

Core Lesson Content

Domain Introduction: Running the Security Program

Welcome to Domain 7: Security Operations. Accounting for 13% of the overall CISSP CAT exam, Domain 7 is the engine room of the security program. While previous domains design, plan, and analyze security, Domain 7 **runs it**.

Even the most secure architecture will fail if operated poorly. Security Operations is the discipline of executing security strategy in daily practice—operating detection tools, running incident lifecycles, maintaining secure baselines, executing rollback change controls, verifying recoveries, and protecting physical facilities.

🧠 Think Like a Manager
Improvisation is the enemy of security operations. Responders must follow documented procedures, playbooks, and change controls rather than attempting ad-hoc technical fixes that can destroy forensic evidence or disrupt business continuity.

This lesson explores the twelve essential topics comprising Domain 7, guiding you from forensic investigations and logging setups to patch management, failovers, and physical site security.

Investigations, Digital Forensics, and Evidence Handling

When security controls fail, organizations must execute structured investigations that conform to legal and forensic standards. Operational analysts must understand evidence handling to prevent tainting evidence before a case escalates.

The Four Primary Investigation Types

  • Administrative Investigations: Conducted internally by HR, compliance, or security teams to evaluate policy violations and inform employment decisions. *Standard of proof: Preponderance of evidence.*
  • Civil Investigations: Dispute resolutions between private parties. Subject to e-discovery regulations to preserve Electronically Stored Information (ESI). *Standard of proof: Preponderance of evidence.*
  • Criminal Investigations: Government prosecution of statutory cybercrime violations. Requires law enforcement involvement. *Standard of proof: Beyond a reasonable doubt (strictest standard).*
  • Regulatory Investigations: Audits conducted by government agencies (such as SEC, FTC, or HHS) into compliance failures. Can result in significant fines and mandated remediation.

Digital Forensics and the Order of Volatility

According to **Locard's Exchange Principle**, every digital interaction leaves a trace. When gathering evidence, analysts must extract data in **order of volatility**—collecting highly temporary memory states before persistent physical storage to prevent data loss:

Volatility Priority Data Category Example Media Preservation Control
1. High Volatility Registers and L1/L2 Cache CPU state buffers Extracted only by specialized forensic tools.
2. Volatile System Memory (RAM) Active running process memory Dump RAM to external media *prior* to system shutdown.
3. Moderate Network Connections Active sockets, ARP tables, routing caches Log commands (`netstat`, `arp -a`) immediately.
4. Persistent Physical Media Hard disk drives, Solid-state drives Construct a bit-stream, write-blocked forensic copy.
5. High Persistence Logs & Off-site Archives SIEM vaults, cloud backup sets Enforce legal hold flags and extract immutable logs.
⚠️ Watch Out
**Never run analysis on original media.** Forensic examiners must always use hardware write-blockers to create a bit-stream image of the drive, and then execute analysis strictly on the copy. Hash values (e.g., SHA-256) must be computed before and after imaging to verify that the copy is identical to the original.

The Chain of Custody

The Chain of Custody is an unbroken paper trail tracking everyone who handled, accessed, or transported evidence during an investigation. Any gaps or undocumented transitions in this record can render the evidence inadmissible in a court of law.

Logging, Monitoring, and Enterprise Visibility

Logging and monitoring provide the operational visibility needed to detect threats, investigate incidents, and fulfill compliance requirements across the organization.

Centralized Logging Architecture and SIEM

To prevent logs from being siloed, systems must forward events in real time to a centralized **SIEM (Security Information and Event Management)** platform. SIEM normalization translates diverse log formats into a common schema, allowing for event correlation across multiple sources (such as mapping a failed VPN login to an internal database query).

💡 Pro Tip: Clock Synchronization
All log sources must synchronize their system clocks using the **Network Time Protocol (NTP)**. Without accurate time synchronization, correlating logs from different systems during an investigation is nearly impossible.

Protecting Log Integrity

Attackers who compromise systems often attempt to delete local security logs to cover their tracks. To preserve evidence, logs must be written to centralized, write-protected, append-only repositories. Access to the SIEM must be strictly controlled, and any log modification attempts must trigger high-priority alerts.

Baselines, Anomalies, and UEBA

To identify threats, security teams must establish a behavioral baseline of normal network and system activity. **UEBA (User and Entity Behavior Analytics)** uses machine learning to profile standard user and device behaviors, generating alerts on deviations (such as a user accessing sensitive files outside of normal business hours) that may indicate active compromise.

Configuration Management and System Hardening

Uncontrolled system modifications are a primary source of vulnerabilities. Configuration management ensures that systems are built, hardened, and maintained in a known-good state.

System Hardening and Security Baselines

A **Configuration Baseline** is a documented standard configuration defined for a system type. Hardening minimizes the system's attack surface by closing unused ports, disabling unnecessary services, and changing factory-default settings. Organizations should align their baselines with standard hardening guides, such as **CIS Benchmarks** or government **DISA STIGs**.

Discovering Shadow IT via Asset Inventories

A complete, accurate asset inventory is a prerequisite for configuration management. Security teams must continuously reconcile active network discovery scans against their **CMDB (Configuration Management Database)** to identify unauthorized or unmanaged systems (Shadow IT). These unmanaged devices represent significant security risks as they bypass patch schedules and monitoring controls.

Provisioning Automation and Application Control

  • Provisioning (Golden Images): Standardized, pre-hardened operating system images ensure that every newly deployed system starts in an approved, secure state, minimizing configuration variations.
  • Infrastructure as Code (IaC): Managing infrastructure settings programmatically (using tools like Terraform or Ansible) provides repeatability, auditable configuration histories, and rapid drift detection.
  • Application Allow Listing: The strongest application control. It permits only explicitly approved applications to execute, blocking all unauthorized software (including malware and untrusted scripts) by default.

Foundational Operational Security Principles

Foundational security operations rely on core, non-technical administrative principles to manage daily access risks and prevent insider threats across the enterprise.

Administrative Access Constraints

  • Need-to-Know: Restricts access to specific records or datasets based on immediate business tasks, even within a classification level.
  • Least Privilege: Restricts user permissions and service account rights to the absolute minimum necessary to perform their roles.
  • Separation of Duties (SoD): Divides sensitive transactions among multiple employees. *Example: The administrator who requests a firewall change cannot be the same administrator who approves it.*
  • Two-Person Integrity (Dual Control): Requires two authorized individuals to act together simultaneously to complete a high-risk operation. *Example: Retrieving recovery keys from a Hardware Security Module (HSM).*

Addressing Operational Insider Risks

Technological controls alone cannot fully prevent insider abuse. Organizations use operational practices to identify and deter malicious activity:

  • Job Rotation: Periodically moving employees to different operational roles. This minimizes the risk of a single employee developing the expertise to circumvent controls and helps detect existing fraud or policy violations.
  • Mandatory Vacation: Requiring employees in sensitive roles to take consecutive, uninterrupted vacation days during which their duties are covered by colleagues. This helps expose unauthorized activities that require the employee's continuous presence to conceal.
🎯 Exam Tip
**Job Rotation** and **Mandatory Vacation** are primarily **detective controls** used to identify fraud, collusions, and unauthorized changes. If an exam question asks how to identify an employee who is actively manipulating local databases for personal gain, mandatory vacation is often the correct administrative answer.

The Incident Management Lifecycle

An incident is an event that violates organizational security policies or threatens the confidentiality, integrity, or availability of enterprise assets. Managing incidents relies on a structured, sequential process.

The 6 Phases of Incident Response (NIST SP 800-61 r2)

resellers must execute the incident response lifecycle in the correct order. Rushing to clean a system before preserving evidence or isolating it can allow attacks to spread or destroy forensic value.

1. PREPARATION: Define policies, draft playbooks, form the CSIRT, and deploy tools.
▼
2. DETECTION & ANALYSIS: Identify events, triage alerts, and confirm incident status.
▼
3. CONTAINMENT: Isolate systems, block attacker IPs, and **preserve evidence**.
▼
4. ERADICATION: Remove malware, delete backdoors, and close vulnerabilities.
▼
5. RECOVERY: Restore systems from clean backups and resume normal operations.
▼
6. LESSONS LEARNED: Document the timeline, analyze gaps, and update playbooks.
⚠️ Watch Out
**Containment precedes Eradication.** res-ponders must isolate compromised systems to stop the attack from spreading and preserve volatile memory *before* deleting malicious files or wiping systems. Attempting to eradicate malware while a system remains connected to the network can alert the attacker, causing them to destroy evidence or execute destructive payloads.

Real-Time Threat Detection & Prevention Tools

Operating a security program relies on deploying and maintaining robust detection and prevention controls across network boundaries and endpoints.

Network Security: IDS vs. IPS

  • IDS (Intrusion Detection System): Passive monitoring. Sits out-of-band (analyzing traffic copies mirrored via SPAN or network TAPs). It detects anomalies or known attack signatures and generates alerts, but **cannot block traffic**. *Key advantage: Does not introduce latency or block legitimate traffic if a false positive occurs.*
  • IPS (Intrusion Prevention System): Active prevention. Sits inline (directly in the traffic path), allowing it to drop packets and block malicious traffic in real-time. *Key risk: False positives can block legitimate business operations.*

Endpoint Protection: EDR and Antivirus

Traditional antivirus relies on signature matching to detect known malware. It is ineffective against zero-days and fileless attacks. **Endpoint Detection and Response (EDR)** monitors system behaviors and telemetry, enabling security teams to detect advanced threats, conduct threat hunting, and automatically isolate compromised endpoints.

Data Loss Prevention (DLP) and Sandboxing

DLP monitors and controls data flows to prevent sensitive data from leaving the organization. **Sandboxing** executes untrusted files in an isolated virtual environment to observe their behavior safely before they are delivered to users.

Patch and Vulnerability Management

New vulnerabilities are disclosed daily. Managing risk requires a structured, repeatable vulnerability management lifecycle: discovery, assessment, prioritization, remediation, and verification.

The Patch Management Lifecycle

Patches must be managed systematically to prevent operational disruptions:

  1. Identify: Monitor vendor alerts and vulnerability advisories.
  2. Assess: Determine if the vulnerability impacts the environment.
  3. Test: Test the patch in a non-production environment to verify that it does not break application functionality.
  4. Schedule: Schedule deployment during approved maintenance windows.
  5. Deploy: Apply the patch across systems.
  6. Verify: Scan systems to confirm the vulnerability is resolved.

Remediation SLAs and Exceptions

Organizations define Service Level Agreements (SLAs) for patch deployment based on vulnerability severity. When patching is not feasible due to compatibility issues, the security team must document a formal exception and implement **compensating controls** (such as network isolation or WAF rules) to mitigate the risk.

Patch Management SLAs

Severity CVSS Score Range Remediation SLA Example Control
Critical 9.0 – 10.0 24 – 48 Hours Emergency change deployment.
High 7.0 – 8.9 14 Days Standard scheduled patch cycle.
Medium 4.0 – 6.9 30 – 90 Days Next scheduled maintenance window.

Production Change Management

Change management is the operational process used to govern all modifications to production systems. Uncontrolled changes are a leading cause of security incidents and system outages.

The Change Management Workflow

Phase Core Activities Security Control Applied
1. Request Submit a detailed Change Request outlining the modification, assets affected, and rollback plan. Ensures changes are documented.
2. Impact Assessment Evaluate potential security, availability, and compliance impacts. Identifies security or regulatory conflicts.
3. Review & Approval The **Change Advisory Board (CAB)** reviews and approves the change request. Enforces division of duties and accountability.
4. Testing Test the change and the rollback plan in a non-production environment. Reduces deployment risks.
5. Deployment Implement the change during approved maintenance windows. Minimizes business disruption.
6. Post-Implementation Review Verify successful deployment and update configuration baselines in the CMDB. Prevents configuration drift.
⚠️ Watch Out
**Emergency Changes** bypass the standard, multi-day CAB review process to resolve critical outages or security incidents immediately. However, they are **not exempt from change control**. Emergency changes require abbreviated, senior authorization before deployment, and a full retrospective CAB review must be completed after implementation to update system baselines.

Disaster Recovery & Backup Strategies

Disaster recovery (DR) ensures that systems and data can be restored securely and efficiently following a major disruption.

1. Full, Incremental, and Differential Backups

Organizations combine different backup strategies to balance backup speed with restore complexity:

  • Full Backup: Copies all data. Simplest restoration but requires the most storage and time.
  • Incremental Backup: Copies only data modified since the last full or incremental backup. Fast to execute, but restoration requires the last full backup and **every subsequent incremental backup** in sequence.
  • Differential Backup: Copies all data modified since the last full backup. Restoration requires only the last full backup and **the latest differential set**, balancing speed and restore complexity.

2. Ensuring Backup Resilience

To defend against ransomware attacks that actively target backup directories, organizations must enforce the **3-2-1 Backup Rule**: maintain **3 copies of data**, across **2 different media types**, with **1 copy stored off-site**. Additionally, implementing **Immutable Backups** prevents data from being modified or deleted during its retention period, ensuring clean recovery points are available.

3. Recovery Site Types

Site Type Equipment Readiness Activation Time (RTO) Financial Cost Best Suited For
Hot Site Fully equipped; data replicated in near-real-time. Minutes to Hours Very High Critical applications; financial transaction systems.
Warm Site Hardware present but requires data restoration from backups. Hours to Days Moderate Non-critical business applications; payroll databases.
Cold Site Facility space with power and cooling; no equipment present. Weeks Low Long-term archiving; non-time-sensitive processing.

Physical Security Operations

Physical security is the foundational layer of any security program. If an attacker gains unauthorized physical access to a system, they can easily bypass software-based security controls.

1. Zoned Access and Mantraps

Physical access controls should use concentric security zones to protect sensitive areas like server rooms. **Mantraps (access control vestibules)** use two interlocking doors where only one can open at a time, preventing tailgating and piggybacking.

2. Environmental Monitoring and Controls

HVAC systems must maintain stable temperature (64°F to 80°F) and relative humidity (40% to 55%) levels. High humidity can cause condensation and short circuits; low humidity increases the risk of static electricity discharges.

3. Gaseous Fire Suppression

Water-based suppression systems can damage sensitive computing equipment. Modern data centers use **Clean Agents (such as FM-200 or Novec 1230)**. These gaseous agents suppress fires by removing heat or oxygen without leaving residue or damaging electronics. *Halon gas systems are banned due to ozone depletion regulations.*

🎯 Exam Tip
**Personnel safety always takes priority over asset protection.** During fire alarms or emergency evacuations, access control doors must fail-safe (unlocking automatically to allow escape), even if this compromises the physical security of sensitive server racks.

Domain 7 Scenario Practice

Applying Domain 7 concepts requires analyzing operational incidents and choosing the correct response sequence. Remember: **Preserve Evidence First → Isolate and Contain Second → Remediate Last**.

Scenario 1 — Responding to active command-and-control beaconing

The Situation: At 2:00 AM, a security analyst detects high-volume outbound traffic from a database server to a known command-and-control (C2) IP address. The database hosts sensitive customer payment data.

The Managerial Response: Rushing to wipe the server immediately violates the incident response lifecycle and destroys crucial evidence. The correct sequence is: (1) **Isolate and Contain** the server by disconnecting its network connection (keeping the system powered on to preserve volatile memory); (2) Capture a **RAM dump** and preserve firewall logs; (3) Identify the malware and entry point; (4) **Eradicate** the malware; (5) Rebuild or restore the server from a clean backup; (6) Document the incident in a **Lessons Learned** review.

Scenario 2 — Investigating Former Developer Code Theft

The Situation: HR suspects a departing developer exfiltrated proprietary source code before resigning. The HR manager wants to immediately wipe and reassign the developer's laptop.

The Managerial Response: Wiping the laptop immediately destroys potential forensic evidence, making legal recourse impossible. The security manager must seize the laptop, document the **Chain of Custody**, place the device in a secure vault, use a hardware write-blocker to create a bit-stream **forensic image**, and execute the analysis strictly on the copy to maintain admissibility in court.

Scenario 3 — Emergency Zero-Day Patching Under Stress

The Situation: A critical zero-day exploit with active, in-the-wild exploitation is published for a public web application gateway. The organization is currently in a pre-product change freeze.

The Managerial Response: An active, critical zero-day exploit requires bypassing the standard change review cycle using the **Emergency Change Workflow**. Security must obtain rapid, senior approval, test the patch in a non-production environment, deploy the fix immediately, and complete a retrospective CAB review after implementation to update system baselines.

Scenario 4 — Mitigating Rogue Switch Changes

The Situation: A network administrator makes an undocumented, ad-hoc change to a core switch configuration on a Friday evening. The change creates a routing loop that takes down critical services, and the administrator cannot remember the original settings.

The Managerial Response: This represents a critical change management failure. Administrators must never deploy changes without a documented **Rollback Plan** and a current configuration backup. To remediate, the team must restore the switch configuration from the latest approved backup baseline in the CMDB and mandate that all future modifications undergo formal CAB review.

Domain 7 Summary: Security Operations Essentials

Domain 7 is where planning meets daily execution. Operating a security program relies on robust logging, real-time threat monitoring, and structured incident management. Responders must follow the correct incident response sequence (Preparation → Detection → Containment → Eradication → Recovery → Lessons Learned), prioritize evidence preservation, and maintain an unbroken chain of custody. Additionally, change and configuration management processes protect systems from vulnerabilities and configuration drift, while disaster recovery strategies ensure business continuity. To succeed on the exam, remember that personnel safety always outranks asset protection, and always verify backup restorability through active testing rather than relying solely on completion logs.

🎯 3 Key Exam Reminders

  • Preserve before Remediating: During security incidents, always preserve forensic evidence (such as volatile RAM state) before taking containment or remediation steps.
  • Uncompromised Auditor Independence: To prevent conflicts of interest, internal audit divisions must report directly to the Board of Directors' audit committee, and auditors must never audit their own work.
  • Backup Restorability Validation: Simply checking backup logs is insufficient. You must validate backups by actively restoring data to an isolated sandbox environment.
