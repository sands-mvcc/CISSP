Introduction

Domain 3 covers security architecture from theoretical models to practical implementation. The core philosophy: security must be built in from the beginning, not added later.

Think of building security like a house foundation - you can't add it after construction. It must be designed in from the start.

This study guide covers five major topics across secure design, security models, reference monitors, security capabilities, and vulnerability mitigation. Use the navigation to explore each area in depth.

Topic 1: Secure Design Principles

Security must be integrated throughout the System Development Life Cycle (SDLC).

SDLC Phases

Activities: Threat modeling, risk assessment, defining security requirements

For an e-commerce site: identify threats like SQL injection, define requirements like "All payment data must use TLS 1.3"

Activities: Security architecture, secure coding, code reviews, SAST

Key Principles

Users/processes get minimum necessary access

Hotel key cards - guests can only access their room, not every room in the hotel

Multiple security layers working together

Medieval castle: outer walls, moat, inner walls, keep - attacker must breach multiple defenses

Topic 2: Security Models

Bell-LaPadula (Confidentiality)

No Read Up: Can't read higher classification

No Write Down: Can't write to lower classification

Secret clearance user: ✅ Read Confidential, ❌ Read Top Secret, ❌ Write to Confidential

Biba (Integrity)

No Read Down: Can't read lower integrity

No Write Up: Can't write to higher integrity

Restaurant kitchen: Chef won't use contaminated ingredients (No Read Down), dishwasher can't modify chef's signature dishes (No Write Up)

Clark-Wilson (Commercial Integrity)

Uses Constrained Data Items (CDIs) and Transformation Procedures (TPs)

Banking: Account balances (CDIs) can only be modified through official transfer procedures (TPs) that maintain balance integrity

Topic 3: Reference Monitor Concept

Three Essential Properties

PropertyMeaning
CompleteMediates ALL access (no bypass)
IsolatedProtected from tampering
VerifiableSmall enough to analyze thoroughly

Key Distinctions

Reference Monitor: Abstract concept (the blueprint)

Security Kernel: Concrete implementation (the actual code)

TCB: All security-critical components (Security Kernel + all other security components)

Topic 5: Vulnerability Assessment

Client Systems

Vulnerabilities: Malware, unpatched software, weak authentication

Controls: Endpoint protection, patch management, MFA, full disk encryption, user training

Server Systems

Vulnerabilities: Unpatched systems, misconfiguration, weak access controls

Controls: Server hardening, network segmentation, IDS/IPS, comprehensive logging

Database Systems

Top Vulnerability: SQL Injection

Prevention: Parameterized queries (prepared statements)

Vulnerable: "SELECT * FROM users WHERE user='" + input + "'"
Secure: Use parameterized query with ? placeholder

Other Controls: Least privilege, TDE encryption, database activity monitoring
